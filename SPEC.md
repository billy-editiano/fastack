# Specification

This project is a monorepo containing several services.


Each service will have its own folder. For example, if the service is `service-a`, the folder name should be `service-a`. If it is an API gateway, the folder name should be `api-gateway`.
service-name/
  helm/
    chart/
      ... (actual helm chart files) ...
    values.sample.yaml
  docker-compose.build.yml
  umbrella-service.yml
  src/
    app/
      ... (app content) ...
  Dockerfile
  pyproject.toml

More explanation:
- svc/helm/chart/ <- this directory is basically generated by the helm cli generator
- `docker-compose.build.yml` only lists services to make building images easier, so we can run `docker compose -f docker-compose.build.yml build`.
- `umbrella-service.yml` content will look like this:

```yaml
# umbrella-service.yml
name: api-gateway
dependencies:
  - source: nginx:latest
    target: mynginx:latest

images:
  - name: "api-gateway"
    prefix: "[[ project.name ]]"
```

---

Based on these criteria, I want you to build these hello world apps following this structure:

- mariadb (simply wrapping the MariaDB Docker image and creating a simple custom chart)
- app (a simple hello world Python FastAPI app that just returns hello world)
- worker (a simple hello world FastAPI app that just returns hello world and connects to the DB via environment variables)

Assume these charts and services can be deployed independently.

## Docker Swarm packaging contract

The project manifest participates in Swarm packaging with the `app`, `worker`,
and `mariadb` artifacts. There is no synthetic deployment artifact and no
root `swarm/stack.yml`.

Each participating artifact owns one deployment fragment:

```text
app/swarm/stack.yml
worker/swarm/stack.yml
mariadb/swarm/stack.yml
```

Each fragment contributes one or more services and may repeat identical shared
resource definitions. Umbrella Packager merges the fragments in manifest order
into one generated `swarm-stack.yml`. The `mariadb` fragment owns the
`mariadb-data` volume; all three fragments may declare the identical `fastack`
overlay network.

Packaged fragments use `published_image(...)` for release image references and
must not contain local-development fields such as `build` or `depends_on`.
The literal database credentials in the example are development-only. Real
deployments should use externally managed Swarm secrets.

The root `umbrella.docker-compose.yml` remains a separate local-development
file and is not a packaged Swarm fragment.
